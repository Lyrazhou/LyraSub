# 《弦字幕》（LyraSub）v260821D 发布说明

## 本轮改进

v260821D 聚焦于长篇文本处理、编辑舒适度、工程恢复可控性与字幕时间锚点可信度。此次更新不改变识别阶段保留的原始词级/字级锚点；所有新功能均在其上增加更安全的编辑与恢复能力。

| 功能 | 变化 | 使用方式 |
|---|---|---|
| LLM 超时 | 新建或未指定超时的配置默认 300 秒；允许范围为 10–3600 秒 | 在“模型服务”设置中调整；超过 30 分钟音频的长稿可考虑 600 秒以上或分段处理 |
| 任务进度 | 删除不可靠的“预计剩余”，保留持续刷新的“已用时” | 长时间 LLM 请求期间可直接观察实际已用时间 |
| 大字号编辑 | 清洗页新增“大字号编辑清洗文本…” | 在独立窗口中以 20 磅字体编辑；可放大/缩小；保存后回写原清洗文本框 |
| 自动保存 | 新增“设置 → 自动保存设置…” | 默认每 45 秒；可设 15–3600 秒或关闭；恢复快照位于工程文件同目录 |
| 字幕合并 | 合并后重新映射到原始锚点时不再错误写入人工时间 | 普通“与下一条合并”会保持“已继承”，只有用户实际修改时间时才显示“人工定时” |

## 自动保存说明

自动保存不会覆盖用户正式保存的 `.lyrasub` 工程。工程已有保存路径且存在未保存改动时，软件会在同一目录写入隐藏恢复文件：

```text
.<工程名>.autosave.lyrasub
```

下次打开工程时，若发现恢复文件，软件会询问是否恢复。正常手动保存成功后，对应恢复文件会被删除。尚未首次保存的新工程没有确定目录，因此不会创建恢复文件；建议在导入音频并命名项目后尽早保存一次。

## “已继承”与“人工定时”的区别

“**已继承**”表示字幕的起止时间直接由识别阶段保存的原始语音锚点推导得出；对普通合并而言，合并后的开始时间来自第一条的首个锚点，结束时间来自下一条的最后锚点，仍属于继承时间。“**人工定时**”表示用户在校对操作中填写的起止毫秒与重新映射出的锚点时间不同，软件将其作为明确的人为覆盖保存。两种状态都会导出到 SRT；区别在于时间来源的可追溯性。

## 超长音频处理建议

本地识别可以持续按语音片段生成锚点，因此电影级音频本身不是锚点系统的逻辑限制。当前规模边界主要在单次 LLM 请求的上下文长度、服务端生成时间及 JSON 输出大小。对于时长超过约 30 分钟、文本非常长或服务端响应不稳定的项目，建议以章节、场景或自然段拆分成多个工程段落后分别执行清洗与切分，再按时间顺序校对导出。

后续电影级批处理可采用“锚点时间块”策略：以 10–20 分钟为一块，优先在长静音或句末切开；每块独立调用 LLM、映射回自身原始锚点，再在全局时间轴中合并。这样可避免单个巨型请求超时、超过模型上下文或返回超大 JSON，同时保持每一块的时间可追溯。

## 验证状态

本版本通过 47 项单元测试及 15 项界面回归测试。v260821D 更新补丁适用于已安装 v260821C 的版本。
