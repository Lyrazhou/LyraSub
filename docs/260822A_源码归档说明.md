# 《弦字幕 Plus》（LyraSub Plus）v260822A 源码归档说明

> 本文档对应《弦字幕 Plus》（LyraSub Plus）v260822A 的完整程序源码归档包。  
> 基础版名称在对比语境中统一写作 **《弦字幕（LyraSub）》**。

## 一、归档目的与边界

本源码归档用于保存《弦字幕 Plus》（LyraSub Plus）v260822A 的可审阅、可继续维护的项目源文件。归档包含桌面应用代码、测试、Windows 安装脚本、构建脚本、项目文档和依赖描述；它不包含体积巨大的构建产物、Wine 前缀、Python 缓存、测试缓存、自动生成的临时目录、已编译安装程序或本地识别模型。

> **归档边界：** 源码包用于复现和维护 Plus 版软件；最终用户安装请使用完整安装程序。识别模型需在软件首次使用时另行下载，不随源码包或安装包强制内置。

## 三、明确排除的内容

为保持归档体积合理、避免把机器专属内容和过期发布物一同保存，以下内容不会进入“完整程序源码”压缩包。

| 排除项 | 原因 |
|---|---|
| `dist/`、`build-win/`、`build-spec/` | 由构建过程生成，可从源码重新构建。 |
| `release/*.exe` | 已另行交付完整安装程序；把二进制放进源码包会造成重复和体积膨胀。 |
| `.wine*` | 构建环境专属 Wine 前缀，体积大且不可作为源码。 |
| `__pycache__/`、`.pytest_cache/`、`.ruff_cache/` | 本机缓存和临时产物。 |
| 本地模型目录 | 模型体积大、可选型号不同，且由用户在软件中按需下载。 |
| API 密钥、用户 Profile 真实凭据 | 安全信息不应进入工程源码或归档。 |

## 七、Windows 应用目录与安装包构建

完整 Windows 发布过程由两步组成：先使用 PyInstaller 生成 `dist/LyraSub`，再由 NSIS 将该目录打包为完整安装程序。发布前必须从当前源码重新构建，不应复用旧版本 `dist/` 或旧的 `release/LyraSub-Plus-setup.exe`。

```bash
# 在项目根目录。Linux + Wine 构建环境示例：
WINEPREFIX=/home/ubuntu/.wine-lyrasub bash tools/build_windows_app.sh

# 构建完整安装程序：
cd installer
makensis setup.nsi
```

构建完成后，应检查应用目录内 `release-manifest.json` 的 `version` 为 `v260822A`，并在新的隔离 Windows/Wine 环境执行静默安装验证。验证重点包括：`LyraSub.exe` 已安装、安装目录可运行、发布清单版本正确、模型目录不被误打入安装包。
