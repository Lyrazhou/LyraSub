# 《弦字幕》（LyraSub）v260821 完整基准版使用说明

> **交付文件：** `LyraSub-setup.exe`。这是新的完整基准安装包，面向 Windows 10/11；它整合了此前识别、模型下载、GPU 兼容、任务中断、工程续作等补丁能力，并加入本次 LLM 与项目工作流改进。

## LLM JSON 导入格式

推荐使用最简 OpenAI 兼容格式：

```json
{
  "name": "我的模型服务",
  "base_url": "https://api.example.com/v1",
  "model": "gpt-4o-mini",
  "api_key": "请在此填入您的密钥",
  "timeout_seconds": 180,
  "headers": {
    "X-Optional-Header": "value"
  }
}
```

导入器同时识别常见字段别名，例如 `api_base`、`apiBaseUrl`、`model_name`、`apiKey`、`token` 与 `extra_headers`。JSON 文件或粘贴文本中的 API 密钥不会写入项目 `.lyrasub` 文件；在用户于设置表单确认“保存”后，软件才将其保存在当前 Windows 用户的加密配置中。

> 请确认服务商提供的是 **OpenAI Chat Completions 兼容接口**，基础地址通常以 `/v1` 结尾，软件会请求 `{base_url}/chat/completions`。模型名称必须与服务商实际可用名称一致。

## 自然意群切分的工作方式

新工作流采用 **LLM 判断语义，软件守护制作约束** 的双层设计。LLM 是默认主策略，负责判断称呼、问答、转折、呼吸、完整短句与两行视觉均衡；软件不再试图把每句填到 15 字，而负责保持原文、解析 JSON、将每一条切分结果重新映射到永久保存的词级/字级时间锚点，并对新增或大改文字标注待复核状态。

例如，对“大家好我是海舟 很高兴今天能够再一次和大家在互联网上空相会”，内置切分提示词明确要求优先形成类似以下的自然阅读结构，而非每 15 字硬断：

```text
大家好 我是海舟

很高兴今天能够再一次

和大家在互联网
上空相会
```

这只是语义策略示例；实际结果由上下文、语气和文本内容决定。若希望针对自己的片源、访谈风格或双语习惯微调，可在 **高级：提示词模板…** 中修改。模板中的 `{max_cjk_chars}` 与 `{max_latin_chars}` 会自动替换为本项目行长设置；若调整失误，点击“恢复切分默认模板”即可回到内置专业模板。

离线兜底切分不会调用网络或 LLM。它保留短完整句，优先在句末断开，只在明显超过单行阅读上限时才借助逗号等标点处理；复杂对白、无标点转写和跨语义关联仍建议使用 LLM 自然语义切分。

## 项目命名、保存与续作

建议导入音频后立即在顶端 **项目** 输入框命名，例如“海舟访谈_第一集”。该名称会作为首次保存 `.lyrasub`、导出 `.srt`、导出清洗文本和导出分行文本的默认名称；用户仍可在文件对话框中临时改名。

任何阶段均可按 `Ctrl+S` 保存。工程会保存已确认的识别锚点、清洗文本、字幕条目、手工时间码、设备/行长设置及未确认编辑草稿。对于已命名工程，只要存在未保存编辑，软件每 45 秒会在工程同目录写入隐藏的 `.工程名.autosave.lyrasub` 恢复副本；下次打开时可选择恢复或丢弃。正在运行的识别、LLM 清洗或切分任务仍需等待完成或手动停止，任务进度本身不支持从中间百分比断点续跑。

## 安装、模型和 GPU

运行 `LyraSub-setup.exe` 后按向导安装。首次使用时，在顶部 **模型管理** 中按需下载“快速”“平衡”或“高精度”模型；模型保存在用户应用数据目录，卸载软件时默认保留，重装后无需重新下载。主识别页只负责选择已下载模型，避免误操作重复下载。

GTX 10 系等 Pascal GPU 会由软件根据 CTranslate2 实际支持的精度自动使用 INT8 路径；现代 Tensor Core GPU 会优先采用 FP16。若需要确认环境，请在识别页点击“运行 GPU 自检”。
