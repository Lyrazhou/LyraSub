# 《弦字幕》（LyraSub）分段音频全局时间轴合并模块设计

## 结论

**应当设计为独立的“分段合并”模块，而不是把现有单工程的“字幕显示偏移量”扩展为多个文件的拼接工具。**两者语义不同：现有偏移量用于让所有字幕整体提前或滞后显示；分段合并的片段起点用于定义某一段本地 `00:00:00.000` 在全片时间轴中的绝对位置。混用会造成重复偏移、难以追溯和边界校对错误。

该模块适合将多个章节 MP3 与其对应的 `.lyrasub` 工程或已导出的 SRT 导入，按用户确认的全片起点计算统一时间轴，提供合并预览、跨段冲突校验、有限编辑和最终 SRT 导出。

## 一、三个必须分离的时间概念

| 时间概念 | 记号 | 示例 | 是否改变原工程 |
|---|---:|---|---|
| 片段本地时间 | `T_local` | 第二章 MP3 中的 `00:00:12.500` | 否；它始终从本段 0 开始 |
| 片段全片起点 | `T_origin` | 第二章本地 0 秒对应全片 `00:42:18.000` | 否；只写入合并工程 |
| 全片字幕时间 | `T_global` | 第二章本地 12.5 秒显示为全片 `00:42:30.500` | 只存在于合并预览与导出 |
| 交付显示偏移 | `T_delivery_offset` | 成片整体提前 200 毫秒显示 | 可选，最后一步统一应用 |

核心换算公式为：

```text
T_global = T_origin + T_local
T_export = max(0, T_global + T_delivery_offset)
```

> 每段在各自工程内原有的“字幕显示偏移”应在导入时被明确处理：导入 `.lyrasub` 工程时可选择“采用该工程的导出时间”；导入已导出的 SRT 时，其时间已是最终本地时间，不能再次叠加同一偏移。

## 二、用户提出的“第二章 0 秒”需求

模块应同时提供两种设置方式，而不是只让用户填一个抽象偏移量。

| 定位方式 | 用户填写内容 | 软件计算方式 | 适用场景 |
|---|---|---|---|
| 与上一段连续 | 上一段之后的额外间隔，例如 `2.000` 秒 | `当前 T_origin = 上一段 T_origin + 上一段音频总时长 + 间隔` | 音频文件按章节无重叠地裁剪 |
| 直接指定全片起点 | 例如 `00:42:18.000` | 直接作为当前 `T_origin` | 用户从剪辑时间线、片头时间码或视频播放器取得准确位置 |

例如：第一章 MP3 时长为 `00:42:16.000`，第二章开头保留了 2 秒的章节空隙，则用户选择“与上一段连续”、间隔填 `2.000` 秒。软件得到：

```text
第二章 T_origin = 00:00:00.000 + 00:42:16.000 + 00:00:02.000
                  = 00:42:18.000
```

第二章本地字幕 `00:00:12.500 --> 00:00:15.000` 导出后即为：

```text
00:42:30.500 --> 00:42:33.000
```

## 三、输入与合并工程格式

建议新建独立合并工程扩展名 **`.lyrasubmerge`**，不修改任何原始章节工程。每一段记录其原文件、时间原点和导入策略。

| 字段 | 说明 |
|---|---|
| `segment_id`、序号、章节名称 | 用于追溯每条最终字幕来自哪个章节 |
| `audio_path` | 可选 MP3 路径；存在时支持跨段试听和自动计算“与上一段连续” |
| `source_kind` | `lyrasub_project` 或 `srt` |
| `source_path` | 章节工程或 SRT 文件的路径 |
| `local_duration_ms` | 优先来自 MP3 容器时长；若无 MP3，只能用最后字幕结束时间作最低估计 |
| `origin_ms` | 用户确认的全片起点 |
| `placement_mode` | 连续、绝对时间、或待确认 |
| `gap_after_previous_ms` | 连续模式下的章节间隔 |
| `imported_entries` | 保留本地起止时间、文本、来源条目编号与风险信息 |

支持 SRT 输入是必要的，因为用户可能已在各章节完成校对；支持 `.lyrasub` 工程输入则更好，因为可保留原始锚点来源、待复核状态和本地显示偏移信息。

## 四、必须内置的合并校验规则

### 1. 片段级校验

| 校验 | 默认行为 |
|---|---|
| 起点未确认 | 禁止最终导出，提示用户填写绝对起点或选择连续模式 |
| 连续模式但上一段没有可用 MP3 时长 | 不猜测起点，要求手动填写绝对全片起点 |
| 当前起点早于上一段起点 | 错误，禁止导出 |
| 章节间隔为负 | 默认不允许；可在高级模式明确允许音频重叠，并进入冲突检查 |
| 源文件发生变更或丢失 | 保留已导入字幕但标红；禁用该段音频试听 |

### 2. 字幕级校验

先在片段内部验证本地起止时间，再换算为全片时间并按 `T_global` 排序。跨段边界必须检查：后一段的第一条全片字幕是否早于前一段的最后一条结束时间。

对于跨段重叠，应显示冲突清单，并提供三种明确动作：保留重叠并标为已确认、把后一段整体向后移动、或在合并表中单独修剪某条字幕的起止时间。软件不应在未告知用户时自动删除或裁切对白。

## 五、建议的独立工作区

建议在现有流程导航之后增加 **“06 分段合并”**，但与普通单音频工程保持独立入口。工作区可分为四个区域。

| 区域 | 主要内容 | 关键操作 |
|---|---|---|
| 片段清单 | 章节序号、MP3、来源工程/SRT、时长、全片起点、状态 | 添加、删除、上下移动、重新导入 |
| 起点设置 | 连续模式/绝对起点、章节间隔、来源偏移采用策略 | 一键重算后续连续片段、锁定已确认起点 |
| 全片校对表 | 全局 SRT 序号、全片起止、章节、本地起止、文本、冲突状态 | 定位、编辑、确认跨段冲突 |
| 合并预览 | 全片时间轴、章节边界标记、当前字幕叠加、跨 MP3 连续试听 | 拖动全片时间轴、自动切换到对应 MP3 与本地位置 |

跨段试听的换算为：当全片播放位置为 `P` 时，找到满足 `origin_ms <= P < origin_ms + duration_ms` 的片段，播放器加载该 MP3 并定位到 `P - origin_ms`。音频之间的章节空隙可显示为静音；没有 MP3 的 SRT 段仍可在全片表中校对，但不能试听。

## 六、实施顺序

| 阶段 | 交付范围 | 原因 |
|---|---|---|
| M1：纯数据与导出 | SRT 解析、片段清单、绝对起点、全局换算、排序、校验、`.lyrasubmerge` 保存 | 先建立可测试、不会损坏原工程的正确时间模型 |
| M2：基本界面 | 添加 SRT/工程、连续与绝对起点设置、冲突表、合并 SRT 导出 | 先覆盖用户提出的核心工作流 |
| M3：合并预览 | 跨 MP3 时间轴、自动切源、当前条目高亮 | 提高边界校对效率 |
| M4：辅助自动化 | 读取 MP3 时长、自动连续排布、章节模板、批量重载 | 降低大量章节的录入成本 |
| M5：高级编辑 | 边界波形、跨段波形拼接、自动静音候选点 | 需要更多媒体处理与性能验证，后置实现 |

## 七、推荐的用户流程

1. 将长片音频按章节或场景裁成多个 MP3，并保留文件顺序。
2. 每个 MP3 单独在普通工程中识别、清洗、切分、校对，并保存 `.lyrasub` 工程或导出 SRT。
3. 打开“分段合并”模块，按顺序加入各章节 MP3 和相应 `.lyrasub`/SRT。
4. 第一段起点通常为 `00:00:00.000`；其后每段选择“与上一段连续”并填写章节间隔，或输入剪辑时间线提供的准确全片起点。
5. 阅读跨段冲突清单，利用全片预览试听每个章节交界处。
6. 导出一份重新编号、全片统一时间码的 SRT。需要成片提前/滞后时，仅在最后导出步骤应用一次全局交付偏移。

> 这样，章节音频从零开始并不是问题：每段的本地锚点仍保留在原工程中，合并工程只负责为它们建立全片坐标系。
