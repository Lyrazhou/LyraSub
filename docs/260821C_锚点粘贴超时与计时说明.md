# 《弦字幕》（LyraSub）v260821C：锚点、整段粘贴、超时与计时说明

## 结论摘要

用户可以在“文本清洗”页的“清洗后文本（可编辑）”框内使用 `Ctrl+A` 全选，并粘贴经其他工具修改后的整段文本。此操作**不会立即改写或打乱原始语音锚点**。真正的文字—时间映射发生在后续“语义切分”生成字幕条目时：软件将切分结果重新同最初识别留下的锚点对齐，并把无法可靠继承时间的新内容明确标为待复核，而不是伪造精确时间。

v260821C 同时修复了长时间 LLM 请求期间“已用时”停滞的问题。对于长文，LLM 超时是固定的单次请求上限，当前不会随字数自动增长；大文本的服务端生成时间更长，确实可能在配置值偏小时发生超时。

| 问题 | 当前行为 | 使用建议 |
|---|---|---|
| 整段粘贴修改后的清洗文本 | 允许粘贴；原始锚点不会在粘贴时改变 | 完成粘贴后重新执行语义切分，并复核黄色条目 |
| 大幅改写或新增段落 | 无法可靠继承的内容会变为“估算”或“无锚点” | 在校对页为这类字幕手工调整时间，或在静音/音乐段落手工插入字幕 |
| LLM 切分“已用时”不变 | v260821C 已改为独立心跳刷新 | 安装 v260821C 补丁 |
| 长文本 LLM 请求 | 固定超时，不随字数自动变化 | 对长文把超时提高至 180–300 秒；极长稿件建议分段处理 |

## 原文每个字的位置如何确定

时间锚点来自**本地语音识别阶段**，而不是 LLM 清洗或语义切分阶段。faster-whisper 识别音频时启用词级时间戳，输出每个词的开始、结束时间与置信度。软件永久保存这些原始锚点，后续清洗、切分、编辑和导出都不覆盖这层数据。

| 文本类型 | 锚点粒度 | 位置来源 |
|---|---|---|
| 中文、日文、韩文等 CJK 文字 | 字符级锚点 | 将识别引擎返回的词级时间跨度按可发声字符均分 |
| 英文及其他空格分词文字 | 词级锚点 | 直接使用识别引擎返回的词级开始与结束时间 |
| 标点 | 保留可见文本，但不作为人工制造的发声锚点 | 不单独产生字幕起始时间 |

> 因此，中文“每个字”的时间是对词级识别跨度的**均分近似**，并非独立的逐字声学强制对齐。它足以支撑字幕切分、继承与人工校对；若需要帧级精修，应在后续波形编辑能力中完成。

## 整段粘贴后，锚点如何继承

按下“确认清洗文本”时，软件只保存用户确认的清洗文本，不会修改识别阶段的原始锚点。随后运行“自然语义切分”时，软件通过序列匹配把切分后的文字单元与原始锚点文本对齐。

| 对齐结果 | 时间处理 | 表格状态 |
|---|---|---|
| 与原始识别文本相同的文字或词 | 继承原有开始、结束时间 | 已继承 |
| 位于两段已知锚点之间的新文字 | 仅在两侧存在可靠时间时插入估算锚点 | 需复核：估算时间 |
| 文本开头、结尾或大幅改写后无法被两侧锚点包围的文字 | 不编造时间 | 需复核：缺少锚点 |

这意味着整段粘贴是安全的，但**不等于所有新文本都能获得真实语音时间**。粘贴后若内容只是去口头语、修正错别字、合并或重新断句，通常大部分文字仍能继承锚点。若内容与原转写差异很大，黄色待复核条目会增加；这正是软件主动阻止错误时间悄然进入 SRT 的保护机制。

## LLM 超时与长文本

LLM 配置中的“超时（秒）”是每一次 OpenAI 兼容 `/chat/completions` 请求使用的固定时间上限。默认值为 **90 秒**，界面允许设置 **10–600 秒**。当前实现不会根据字数、字符数或预计输出长度自动放宽该值。

长文本通常会增加上传、模型理解和生成 JSON 切分结果的时间。如果服务在该时长内没有返回完整 HTTP 响应，客户端会将其视为请求失败并显示可复制诊断；这不一定表示 API 配置错误，可能只是所选模型或服务在该篇文章上需要更长时间。

建议先把常规请求保留在 90 秒左右；当一篇长稿反复出现超时而网络稳定时，调到 180 秒或 300 秒。对于特别长的内容，按自然章节或段落拆分后分别清洗、切分，通常比无限增大超时更可靠，也便于复核锚点边界。

## v260821C 计时修复

此前“已用时”依赖 LLM 客户端主动上报阶段进度。LLM 请求发送后到服务端返回前，通常没有新的阶段回报，因此界面会停留在上一次数字。v260821C 增加了每 250 毫秒运行的独立界面计时心跳：无论请求是否有新的服务端消息，已用时都会持续刷新；当进度已知时，预计剩余也会按当前进度同步更新；任务完成、失败或停止时心跳会自动停止。

本修复已通过全部自动化检查：44 项单元测试和 13 项界面回归测试均通过。v260821C 补丁适用于已安装 **v260821B** 的版本。
