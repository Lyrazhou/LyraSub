# v260821D 长文本、编辑与保存体验设计

## LLM 超时与进度

LLM 配置的默认超时改为 **300 秒**，可设置范围扩展为 **10–3600 秒**。设置界面固定显示提示：处理时长超过 30 分钟的音频转写稿时，模型输入与输出都可能明显变长；应按服务商稳定性把超时提高到 600 秒或更高，或按章节分段处理。任务进度区域只保留“已用时”，不再显示基于百分比推算的“预计剩余”，避免将服务端不可观测的生成时间包装为不可靠的预测。

## 大字号清洗文本编辑

文本清洗页新增“大字号编辑…”按钮。它打开独立窗口，使用 20 磅编辑字体显示当前清洗文本，并提供字号增减、保存和取消。保存时一次性写回原有“清洗后文本”框，因此既有“确认清洗文本”与锚点映射流程保持不变。

## 自动保存

自动保存默认每 **45 秒**运行一次，仅在工程已命名保存且存在未保存改动时写入恢复快照。恢复文件与用户的 `.lyrasub` 工程位于同一目录，文件名为：

```text
.<工程名>.autosave.lyrasub
```

新增“设置 → 自动保存设置…”入口，可选择 15–3600 秒的间隔或关闭自动保存。该偏好使用当前 Windows 用户的本地设置保存；工程另存为后，恢复快照会跟随新工程路径创建。首次尚未保存工程时没有目标目录，因此不会产生恢复文件，提示用户先保存一次工程。

## 合并后的锚点继承

“与下一条合并”会重新依据完整的原始词级/字级锚点计算合并后条目的起止时间。保存表格时，只有表格中用户填写的时间**不同于重新映射出的时间**，才创建 `manual_start_ms` 或 `manual_end_ms`。这取代此前“不同于合并前首条时间就视为手工时间”的错误比较，避免普通合并把“已继承”误标为“人工定时”。

## 超长音频

本地识别可以连续读取长音频并逐段输出锚点；真正的规模边界主要在 LLM 的上下文窗口、单请求生成时间与 JSON 输出大小。当前版本应将超长项目按章节或自然段分段清洗与切分。后续的电影级批处理应以 10–20 分钟的锚点时间块为单位，优先在长静音或句末边界切分；每块单独调用 LLM 并映射回其原始锚点，最后按时间顺序合并条目。这样可以避免单个巨型请求超时或超过模型上下文，同时不破坏全片统一的全局时间轴。
