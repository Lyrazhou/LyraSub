# 《弦字幕 Plus》v260821H 发布说明

**版本：v260821H**  
**产品：弦字幕 Plus（LyraSub Plus）**  
**发布形式：v260821G → v260821H 累积差分补丁**

> 本版本将字幕翻译、双语输出和外部字幕接入纳入同一工程工作流。原有本地识别、清洗、语义切分、锚点映射、MP3/MP4 校对预览与 SRT 导出能力保持不变。

## 本版重点

| 功能 | v260821H 行为 | 对既有工程的影响 |
|---|---|---|
| LLM 批量翻译 | 按模型服务设置的字符上限分批发送多个字幕条目；不会逐条请求。每条字幕携带稳定 ID，返回结果必须逐项对应才会写入工程。 | 新增译文字段，不改动原文、时间轴或锚点。 |
| 翻译批次上限 | 模型服务设置中新增“翻译每批字符数”，默认 **8000**，可设为 **1000–100000**。 | 保存在本机模型服务配置中，不写入工程文件。 |
| 双语字幕输出 | 可选择导出原文、仅译文或双语两行；双语可选择“原文在上”或“译文在上”。 | 双语模式会自动启用两行布局。 |
| 外部 SRT 导入 | 可直接导入 `.srt`，每条导入字幕均以其原始时间码作为人工定时。 | 导入条目无语音锚点，不适用自动继承或锚点重映射。 |
| 工程另存为 | 通过“另存为”保存到新路径并自动切换当前工程引用。 | 原工程文件不会被删除或覆盖；旧路径的自动保存恢复快照会被清理。 |

## 批量翻译工作流

在 **校对导出** 页填写“原文语言”和“目标语言”后，点击 **LLM 批量翻译**。系统读取当前活动模型服务中的“翻译每批字符数”，仅在字幕条目之间拆分批次；任何一条超出该上限的字幕会单独成批，从而不会在句中截断。

翻译请求使用字幕 ID 和文本组成结构化数组。系统会检查每一个输入 ID 是否恰好收到一个非空译文。若 LLM 遗漏、重复或新增 ID，整个任务将报错且不会将半成品写回工程。任务面板会显示当前批次、已用时、进度条和停止按钮；用户停止任务时，未完成结果不会写入。

翻译完成后，可在同一页面选择三种输出模式。**导出原文**沿用原有字幕文本；**仅导出译文**在没有译文时回退为原文并在时间轴检查中给出提示；**双语两行**会压缩各自内部换行后形成固定两行，并按用户选择的上下顺序写入标准 SRT。

| 输出模式 | SRT 文本示例 |
|---|---|
| 导出原文 | `大家好` |
| 仅导出译文 | `Hello, everyone.` |
| 双语两行（原文在上） | `大家好`<br>`Hello, everyone.` |
| 双语两行（译文在上） | `Hello, everyone.`<br>`大家好` |

## 外部 SRT 导入

使用顶部工具栏的 **导入 SRT**，选择 UTF-8 或 UTF-8 with BOM 编码的 `.srt` 文件。系统保留每条字幕的文本、开始时间和结束时间，将其转换为项目中的人工定时条目。由于外部 SRT 并不包含语音识别产生的词级时间锚点，导入后工程的锚点集合为空，条目的 `anchor_ids` 也为空。

这类工程仍可直接校对文字、调整起止时间、插入或删除人工定时条目、调用 LLM 批量翻译并导出 SRT。如需播放预览，可随后导入与外部 SRT 同步的 MP3 或 MP4 媒体；未导入媒体时，校对页会保留字幕编辑与导出能力，但不会提供播放预览。

## 工程格式与兼容性

工程格式升级为 **schema v5**，新增每条字幕的 `translation_text`，以及项目级的 `subtitle_output_mode`、`bilingual_order`、原文语言名称和目标语言名称。v1–v4 工程可以继续打开；由于其不含译文和双语设置，系统会使用空译文、原文输出、原文在上的默认值。v260821H 保存工程后将使用 schema v5。

> 建议在将既有工程尝试不同语言或不同字幕风格前，先使用 **另存为** 建立分支。另存为只创建新工程文件并切换当前工作对象，不会更改原工程。

## 升级与验证

请在已安装 **v260821G** 的《弦字幕 Plus》目录中运行固定文件名 `LyraSub-patch.exe`。补丁会进行基线版本校验，并在写入前保留可回滚备份。升级完成后，可在“关于”窗口确认版本为 **v260821H**。

本版本已完成 Python 代码格式化与静态检查；完整单元测试和离屏界面冒烟测试均已通过。测试覆盖批量翻译分批与返回 ID 校验、双语 SRT 上下顺序、schema v5 保存恢复、外部 SRT 的人工定时导入、工程另存为路径切换，以及双语播放预览。
