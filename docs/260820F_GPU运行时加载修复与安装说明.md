# 《弦字幕》（LyraSub）v260820F GPU 运行时加载修复与安装说明

> **适用版本：** 已安装 **v260820E** 的《弦字幕》（LyraSub）。运行固定文件名 `LyraSub-patch.exe` 后，软件将升级为 **v260820F**。

## 这次修复解决什么问题

用户设备的 GTX 1060、NVIDIA 驱动、CUDA 12 Toolkit 和 CTranslate2 CUDA 设备枚举均已正常；但 v260820E 的安装版在 Windows/PyInstaller 环境下即使进程 PATH 包含 CUDA `bin`，仍可能无法由原生扩展正确解析 `cublas64_12.dll`、`cublasLt64_12.dll` 与 `cudnn64_9.dll`。

v260820F 不会打包数百 MB 的 CUDA/cuDNN 运行库，也不会改写系统 PATH。它会在 GPU 自检和 GPU 模型加载前，**显式注册可信的 DLL 目录**，并保持注册句柄在进程生命周期内有效，从而让 CTranslate2/faster-whisper 的原生 DLL 可找到 CUDA 12 与 cuDNN 9 依赖。

| v260820F 行为 | 说明 |
|---|---|
| 自动发现 CUDA 12 | 扫描 `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12*\bin` 与 `CUDA_PATH`。 |
| 自动发现系统 cuDNN 9 | 扫描 `C:\Program Files\NVIDIA\CUDNN\v9*\bin`，并兼容 `LYRASUB_CUDNN_BIN`、`CUDNN_PATH`、`CUDNN_HOME`、`CUDNN_ROOT` 环境变量。 |
| 显式注册 DLL 目录 | 使用 Windows 的 DLL 目录注册机制，不再只依赖冻结程序不稳定的 PATH 搜索。 |
| 更细诊断 | 诊断会显示已注册目录，并区分“未发现文件”和“发现 DLL 但其依赖或版本无法加载”。 |
| GPU 初始化报错 | 强制选择 GPU 且模型无法载入时，会保留原始异常并附加完整 GPU 自检报告，便于复制反馈。 |

## 应用补丁后如何验证

首先退出 LyraSub，再运行 `LyraSub-patch.exe`。补丁仅适用于 v260820E，安装后会备份原 `LyraSub.exe` 与发布清单至 `.update-backup\v260820F`。

重新正常双击启动 LyraSub（**不需要**再通过 PowerShell 传入临时 PATH），打开左侧 **“模型与设备”** 页面，点击 **“NVIDIA GPU 环境自检”**。

| 预期自检信息 | 表示的含义 |
|---|---|
| `已显式注册 DLL 目录：...CUDA...\bin` | v260820F 已发现并注册本机 CUDA Toolkit。 |
| `cublas64_12.dll：可加载` | CUDA 12 cuBLAS 基础库可供 GPU 推理使用。 |
| `cublasLt64_12.dll：可加载` | CUDA 12 cuBLASLt 库可供 GPU 推理使用。 |
| `cudnn64_9.dll：可加载` | cuDNN 9 运行时完整且可解析。 |
| `CTranslate2 CUDA 设备数：1` | CTranslate2 能看到 GTX 1060。 |

若前三项都为“可加载”，即可选择 **NVIDIA GPU** 并使用“快速”模型做短音频识别测试。对于 6GB 显存的 GTX 1060，建议先使用“快速”模型；“高精度”模型可能因显存容量不足而不适合 GPU。

## 什么时候才需要安装或重装 cuDNN

**仅在 v260820F 自检中 `cudnn64_9.dll` 仍不可加载时**，才需要安装系统级 cuDNN 9。已确认 CUDA 12 的两个 cuBLAS DLL 存在时，不建议为了这个问题重装 NVIDIA 显卡驱动或 CUDA Toolkit。

> 不建议从其他 Python、WhisperX 或 WorkBuddy 环境中单独复制一个 `cudnn64_9.dll` 到 LyraSub 目录。cuDNN 9 通常包含多个互相依赖的 DLL；只复制单个文件会引入版本混用与后续依赖缺失风险。

## 官方 cuDNN 9 安装方案（Windows 10/11 x86_64）

请只从 NVIDIA 官方下载。推荐使用图形安装器；它会将可用的 CUDA 版本包含在一个安装包内并按界面选择安装。NVIDIA 的 Windows 安装文档也明确将图形安装器作为常规安装方式。[1]

| 项目 | 操作 |
|---|---|
| 官方下载页 | 打开 [NVIDIA cuDNN 下载页][2]。如页面要求，请登录或注册 NVIDIA Developer 帐号并接受许可协议。 |
| 推荐选择 | `Windows` → `x86_64` → `Windows 10/11` → `CUDA 12` → `exe (local)`。 |
| 可固定使用的版本 | [cuDNN 9.12.0 Windows x86_64 图形安装器][3]；官方页面提供 `cudnn_9.12.0_windows.exe`。 |
| 安装 | 双击 EXE，按图形向导完成；保持 CUDA 12 组件被选择。无需卸载现有 CUDA 12.6/12.9。 |
| 安装目录 | 通常位于 `C:\Program Files\NVIDIA\CUDNN\v9.x\bin`。v260820F 会自动扫描该路径，无须手动将其加入 PATH。 |
| 验证 | 关闭并重新打开 LyraSub，在“模型与设备”页重新执行 GPU 自检。 |

NVIDIA 也提供 ZIP 手动安装方式，但官方文档明确指出它不是面向一般用户的安装器。若确实使用 ZIP，必须将完整包的 `bin\cudnn*.dll` 复制到 `C:\Program Files\NVIDIA\CUDNN\v9.x\bin`，再将该 `bin` 目录加入 PATH。[1] 对本软件场景，优先使用 EXE 图形安装器。

## 若仍失败，应提供什么信息

请复制 v260820F 自检窗口中的**完整文本**。其中应包含“已显式注册 DLL 目录”、每个 DLL 的候选文件路径，以及具体的 `OSError`。不要只截取顶部的“GPU 初始化失败”。这能区分以下情况：

| 报告特征 | 下一步 |
|---|---|
| CUDA DLL 可加载，cuDNN 不可加载 | 安装或修复官方 cuDNN 9。 |
| 已发现 DLL 文件但仍不可加载 | 需要继续检查 DLL 的子依赖、架构或版本冲突；将完整原始异常反馈。 |
| 未注册 CUDA 目录 | 说明 CUDA 未安装在默认位置；可设置 `CUDA_PATH` 或在后续版本配置自定义目录。 |
| 三项可加载但模型仍失败 | 将强制 GPU 模式下的“原始异常 + 自检报告”完整复制反馈，进一步检查显存与模型载入。 |

## 本次验证记录

v260820F 已完成代码格式化、静态检查、全量自动化测试和离屏界面测试。已在隔离 Windows/Wine 环境从 v260820E 状态应用补丁，验证了版本由 v260820E 升至 v260820F、覆盖前备份、清单更新及应用持续启动。实际 CUDA/cuDNN 成功加载仍需在您的 GTX 1060 实机上通过上述自检确认。
